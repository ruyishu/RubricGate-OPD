# START HERE：M0 toy pilot（1–2 天，单卡或纯 CPU 逻辑验证）

目标**不是**训出好模型，而是先回答一个可以毁掉整个 idea 的问题：

> 合法换序真的会被 token-OPD / STRIDE 式早停罚吗？罚得有多重？rubric 门控能不能把它救回来？

## M0-1 环境：符号化 toy 任务（半天）

不接真实 LLM，不接真实 benchmark。先写一个纯 Python 的确定性状态机：

```
动作: a, b, c, d
前置: a: ∅ | b: {a} | c: {a} | d: {b, c}
成功: 依次完成 a, (b,c 任意序), d
非法: 未满足前置就执行 -> 失败；重复执行为无效动作
```

教师策略：在 `{b,c}` 都可执行的状态下，以概率 $p$ 先 `b`（$p\in\{0.5,0.8,0.95\}$），用来模拟「教师有顺序偏好」。
学生：先给一个带随机偏好的初版策略（例如以 0.5 先 `c`）。

产出：`research/toyenv.py`，要求有 CPU 单测（状态转移、非法判定、成功判定）。

## M0-2 三种监督的对照（半天）

在同一条学生轨迹上，分别算：

1. **token-OPD 代理**：用离散动作上的 reverse-KL（把每个动作当成一个 token 位置）近似，看学生选 `c` 时损失多大；
2. **STRIDE 式早停代理**：以「教师对该动作的概率」为教师认可度，跌破阈值即截断，统计学生被截断的频率；
3. **RubricGate**：DAG 解锁池 + 三态门控，统计放行/改造/早停各占比。

产出：一张表（学生换序率 × 教师偏好强度 × 三种方法下的误杀率/成功率代理）。

## M0-3 判读（半天）

- 若 $p=0.95$ 时 token-OPD 的误杀率很高而 RubricGate 接近 0 → H1/H2 在这个 toy 上成立，值得往真实 benchmark 推。
- 若误杀率很低（说明教师顺序偏好其实不影响）→ idea 的动机被削弱，先别写代码，回头重新找动机。
- 若 RubricGate 也误杀（DAG 判错）→ 问题在 rubric 构造，先解决它。

## 交付门槛

- 有可复现的命令与固定随机种子；
- 表格写进 `results/`，结论写进 `docs/STATUS.md`；
- 明确标注这是符号化 toy，**不能**当真实 agent 上的证据。

## 之后（M1）

M0 通过后：在 τ²-bench 的一个子集上标注 20–30 条任务的 DAG-Rubric，人工核对可解路径，量一下「rubric 一致率」，再决定是否真接模型训练。
