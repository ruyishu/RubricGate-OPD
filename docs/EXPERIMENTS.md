# 实验设计

跑过的只有 CPU 检查。下面的探针和训练都没做。不写预期涨点。

## 命题

- **H1，未验证。** 真实老师下，「不同但没错」的步会被 token KL 和同状态动作匹配压分。要分开看六类：顺序不同、换了工具、调用粒度不同、多了无害步骤、真的走错、关键步走错导致后面失效。脚本夹具不能证明这件事。
- **H2，只检查了规则。** 环境证实的新评分点得正分；没变化得 0；弄坏已有评分点得负分。推进步的老师 KL 系数为 0，确认出错的步为 1。不一致的动作不会因为「像不像老师」得到负奖励。
- **H3，未验证。** 同一学生、同一数据和同一预算下，按步评分点训练优于整条轨迹打一次分，并与 DARS 持平或更好。评测用基准自己的成功判定。
- **H4，未验证。** 同样的逐步奖励下，KL 只在出错步打开，优于 KL 全程打开。否则开关没有贡献。
- **H5，未验证。** 在相同干预预算下，按评分点纠正或早停，优于按师生分歧做同样的干预。老师代打的进展不进学生回报。

## 阶段

1. **探针。** 学生在真实环境里采样。老师在学生到达的状态上采样动作。人工把不一致的步标成上面六类，再算 token 侧和动作匹配侧的分数。六类里「没错」的占比很小，或者没有被明显压分，就停止。
2. **评分点质量。** 大约 50 道题，先用 \(\tau^2\)-bench 和带单元测试的代码题。报告和人工逐步判断的一致程度、过滤掉的坏点比例、每题老师调用次数。不一致就先改生成流程。
3. **只打分的训练。** 不纠正、不早停。对照：终局 GRPO、ActionOPD、白盒 token OPD、同一套评分点但整条轨迹打一次分、DARS。至少三个种子。KL 全程打开是必做对照。
4. **路径干预。** 只有 H1 成立才做。对照是「只打分」和「按分歧、用同样预算干预」。然后换第二个基准，并消融平铺评分点、人工评分点、故意写错的评分点、中性步的 KL 权重、纠正项的系数。
