# 实验设计

已跑的只有 CPU 机制夹具 `results/m0-mechanism-001`。下面其余格子都没跑。不写预期涨点。

## 命题

- **H1，未验证。** 真实教师在可换序任务上，会把合法换序打成低奖励或提前停掉。机制夹具不能证明这件事，因为脚本分布本身就把换序的概率设低了。
- **H2，只在夹具上验证了规则。** 正确 DAG 下，环境证实的已解锁子目标得正分；清单外、重复、没生效、未造成破坏的未解锁动作得 0；只有破坏已完成子目标得负分。师生动作一致但环境失败时不得分。错误 DAG 会把合法换序打成 0。
- **H3，未验证。** 在相同训练预算下，少误罚能提高成功率。
- **H4，未验证。** 相对 DARS 式打分的额外收益来自「是否干预」，不是来自依赖奖励本身。夹具里 v1 和势能差的符号已经一致，所以不能靠打分表声称超过 DARS。

## 夹具已经包含的对照

100 条四步模板，类别固定：标准顺序、合法换序、未解锁就付款、清单外查询、重复、环境失败、未解锁的非提交动作、破坏已完成子目标。

对照是动作匹配（偏好 0.5/0.95，候选数 1/3）、平铺清单、势能差、错误 DAG、只打分、以及带接管的记账。GraphOPD 没有放进夹具：它的随机游走重加权不是这几条规则能忠实复现的，写一个简化代理会把原文方法说错。

## 还要跑的

1. **真实教师探针。** 用一个会开放动作概率或能重复采样的教师，在含可换序子目标的任务上估计合法换序的实际低分比例。这一步过不了，就不要做训练。
2. **相同预算的成功率。** 学生和数据划分固定。对照至少包括 token-OPD、同状态动作匹配、只打分不干预、无依赖清单、教师一次给多个候选动作。
3. **自动清单。** 前面使用人工或规则清单。最后再换成自动生成的清单，看错误标注会吃掉多少收益。
4. **第二阶段。** 只有探针说明误罚或误停确实存在，才比较继续、接管、早停。接管实验必须分开报告学生回报和教师代打进展。

基准仍按这个顺序考虑：自建可换序工具任务、\(\tau^2\)-bench、ALFWorld、WebShop。主指标是成功率和相同预算下的环境步数。诊断指标是合法动作被压分的比例、真违规的识别、清单外动作被误罚的比例、错误 DAG 下的误伤、后段状态覆盖。没有结果的格子保持空白。
