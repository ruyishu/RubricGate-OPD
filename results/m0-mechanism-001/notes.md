# M0 机制检查

命令：`python -m research.run_m0`

100 条手写模板轨迹，每条 4 步。`open_bc` 表示这一步开始时 b 和 c 都已解锁。标签来自正确 DAG 和环境结果。动作匹配行是脚本分布下的期望，不是抽样结果。

## 这张表能说明什么

- 正确 DAG 上，RubricGate v1 和势能差的奖励符号一致：新完成的子目标为正，破坏已完成子目标为负，其余为 0。势能差没有实现 DARS 的下游衰减，不能当成 DARS 复现。
- 清单外动作平均奖励 0.0000，负奖励比例 0.0000。未解锁的付款步骤平均奖励 0.0000，负奖励比例 0.0000。工具名对了但环境没生效时平均奖励 0.0000。
- 平铺清单给未解锁付款步骤正奖励的比例是 1.0000。
- 把 c 错标成必须在 b 之后后，合法换序那一步的平均奖励是 0.0000。图错了，打分就跟着错。
- 动作匹配的期望奖励等于学生动作在教师分布中的概率，候选数 k 不改变这个期望。b/c 都可做且教师以 0.95 偏好 b 时，老师那一步的期望奖励是 0.9500，合法换序那一步是 0.0500。k=1 时这步奖励为 0 的概率是 0.9500；k=3 时期望仍是 0.0500，奖励为 0 的概率是 0.8574。偏好降到 0.50 且 k=3 时，期望奖励是 0.5000，奖励为 0 的概率是 0.1250。
- 接管记账：100 条轨迹里，学生回报与逐步学生奖励不一致、或接管步被记成正奖励的次数是 0。教师代打完成的子目标记在 `teacher_progress`，没有加进学生回报。

## 这张表不能说明什么

脚本偏好把「合法换序匹配分低」写进了分布，所以那个差距不能证明真实 OPD 存在同样严重的误罚。本表也没有训练，不能证明少误罚或多出来的接管能提高成功率。
