# M0 机制检查

命令：`python -m research.run_m0`

100 条手写模板轨迹，每条 4 步。`open_bc` 表示这一步开始时 b 和 c 都已解锁。标签来自正确 DAG 和环境结果。动作匹配行是脚本分布下的期望，不是抽样结果。`scorer=rubricgate_v1` 是只打分、不改路径的评分点奖励。

## 这张表能说明什么

- 正确 DAG 上，评分点奖励和势能差的符号一致：新完成的子目标为正，破坏已完成子目标为负，其余为 0。势能差没有实现 DARS 的下游衰减，不能当成 DARS 复现。
- 清单外动作平均奖励 0.0000，负奖励比例 0.0000。未解锁的付款步骤平均奖励 0.0000，负奖励比例 0.0000。工具名对了但环境没生效时平均奖励 0.0000；同一步的动作匹配期望是 0.9500。
- 换工具（用手机号查到同一个订单）：评分点四步奖励是 [1, 1, 1, 1]；第一步的动作匹配期望是 0.0000。拆开调用：评分点四步奖励是 [1, 0, 1, 1]；补完 b 的那一步动作匹配期望是 0.0000。夹具里一步的效果就是它的目标子目标，所以「换工具也算完成」是构造出来的。真实检查器能不能认出来，要到 P1 才知道。
- 平铺清单给未解锁付款步骤正奖励的比例是 1.0000。
- 把 c 错标成必须在 b 之后后，合法换序那一步的平均奖励是 0.0000。图错了，打分就跟着错。
- 动作匹配的期望奖励等于学生动作在教师分布中的概率，候选数 k 不改变这个期望。b/c 都可做且教师以 0.95 偏好 b 时，老师那一步的期望奖励是 0.9500，合法换序那一步是 0.0500。k=1 时这步奖励为 0 的概率是 0.9500；k=3 时期望仍是 0.0500，奖励为 0 的概率是 0.8574。偏好降到 0.50 且 k=3 时，期望奖励是 0.5000，奖励为 0 的概率是 0.1250。
- `gate_counts.csv` 按类别列出继续、接管、停止的次数，以及该类别的学生回报和老师代打进展之和。接管记账的具体断言在 `research/test_mechanism.py`。

## 这张表不能说明什么

脚本里老师的动作名和偏好都是写死的，所以「换序、换工具、拆开调用的匹配分低」是分布里写进去的，不能证明真实 OPD 存在同样严重的误罚。本表也没有训练，不能证明少误罚或接管能提高成功率。
