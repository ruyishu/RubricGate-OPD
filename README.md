# RubricGate-OPD

多轮 agent 的评分点级 On-Policy Distillation。

**监督看「这一步让哪个评分点成立了」，不看字像不像老师，也不看动作像不像老师。**

评分点写成要达到的状态。换一种顺序、换一个工具、把一次调用拆开、多查一次无害信息，只要状态对了，主奖励就不罚。破坏已经成立的评分点，或者前置没满足就做提交动作，才算错。

训练时主损失是按这个逐步奖励做的策略梯度。老师只在两种状态上进入梯度：确认出错，以及连续几步评分点都没动（卡住）。白盒老师用这一步的 token KL；黑盒老师在这些状态上局部重采样学生候选，推进了评分点的候选排在「只是像老师」的候选之前。纠正和早停是后一阶段，老师代打得到的进展单独记账。

## 和最近工作的差别

- **token OPD**：每个 token 都对老师做 KL。措辞、顺序、做法不同都会被拉回去。
- **ActionOPD（2610.19820）**：改成「这一步的动作像不像老师抽到的动作」。换序、换工具、拆开调用仍然会被压分。我们认为动作一致也不等于环境里办成了。
- **ROPD（2605.07396）**：已经用评分点代替老师 logit，但是整份回答打一次分，实验在单轮推理上。
- **DARS（2610.01207）**：按子目标和前置关系给逐步奖励。它是 RL 的奖励设计，依赖图靠领域规则，没有老师示范，也不改学生怎么往下走。2026-10-01 的预印本，未查到录用记录。
- **GraphOPD（2610.08959）**：用执行依赖和师生分歧决定哪些步多蒸馏。它改损失权重，不判断这一步该不该算错。

只做「按依赖给分」会和 DARS 撞车，只做「用评分点做 OPD」会和 ROPD 撞车。还没验证的部分是：多轮环境里按步打分；老师只在出错或卡住时进入梯度；老师写的评分点优于不看老师轨迹写出的评分点。后一阶段才是按评分点决定纠正或早停。
