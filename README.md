# RubricGate-OPD

多轮 Agent 的动作级 On-Policy Distillation。

**师生动作不一致时，用依赖关系和环境结果判断学生是否还在合法解里；不把老师的顺序偏好当成对错。**

例子：先查库存 `a`，再查价格 `b` 和查促销 `c`（顺序无关），最后付款 `d`。老师走 `a→b→c→d`，学生走 `a→c→b→d`。只和老师当前这一步比，会把先做 `c` 判低。付款如果发生在 `b`、`c` 完成之前，第一版不加分；第二阶段才考虑接管。查询类动作即使不在清单里，也保持中性。

第一版只改这一步的奖励，不改采样路径。清单里没写的查询或准备动作，只要没破坏已完成的子目标，奖励记 0。工具名对了但环境没有完成子目标，也不算完成。

老师接管和早停是第二阶段，还没有训练证据。老师代打得到的进展不能记到被替换的学生动作上。

## 当前状态

设计文档，加一个 CPU 机制夹具。**没有训练代码，没有真实模型分数。**

机制夹具只检查规则有没有写错。它用脚本教师算出「合法换序的匹配分更低」，这个差距是分布里写死的，不能证明真实 OPD 真有这么严重的误罚。证据边界写在 [STATUS.md](docs/STATUS.md)。

## 和最近工作的差别

- **ActionOPD（2610.19820）**：在学生当前状态下，按和学生动作是否匹配老师抽到的动作给奖励。强顺序偏好时，合法换序仍会得低分。
- **GraphOPD（2610.08959）**：用执行依赖和师生分歧决定哪些步多蒸馏。它调整损失权重，不判断这一步该不该接管。
- **DARS（2610.01207）**：用带前置条件的子目标给分步奖励。允许换序。它不改变 rollout，也不能把「在线/离线」当成差别：附录 E 的 WebShop 续训会逐轮读前缀。
- **GEAR（2606.03361）**：给完整回答做 DAG rubric 汇总，防止前置不成立还拿下游分。
- **CD-OPD（2610.25359）**：老师接管后，用依赖图整理上下文再交给学生。图不负责判断换序合不合法。

「依赖图 + 分步奖励」本身撞 DARS。本仓库剩下要验证的是：不一致时学生是否仍在合法解里，以及据此减少错误干预之后，训练是否更好。第二点还没有证据。
